# Decisions

Approved decisions that shape the implementation. Update this file when a decision changes.

| #   | Decision               | Detail                                                                                                                                                                                                 |
| --- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| D1  | Stack                  | Next.js 16 (App Router), TypeScript, Tailwind CSS v4, shadcn/ui, PostgreSQL, Drizzle ORM, Auth.js, Zod, React Hook Form, Vitest, Playwright. Single full-stack repository.                             |
| D2  | Hosting                | Vercel (Fluid compute, Node runtime) and Neon PostgreSQL, with a Neon branch per preview deployment. No other infrastructure.                                                                          |
| D3  | Language and direction | Persian (`fa`) is the primary UI language; layout is RTL. Logical CSS properties only.                                                                                                                 |
| D4  | Calendar               | The user-facing calendar is Solar Hijri (Jalali); the week starts on Saturday. The domain and database stay calendar-agnostic: ISO `YYYY-MM-DD` dates and `period_start`/`period_end`.                 |
| D5  | Authentication         | Email and password via Auth.js. No public self-registration; users are provisioned by the seed. No Admin role. Isolated behind `getActor()`.                                                           |
| D6  | Password hashing       | argon2id.                                                                                                                                                                                              |
| D7  | Night-rest rule        | A Night (`N`) on date D requires OFF on D+1 (`N→M`, `N→E`, `N→ME`, `N→N` are all invalid), across schedule boundaries. Temporarily allowed while editing; blocks FINALIZE and SUBMIT. Not overridable. |
| D8  | Authorization          | Enforced in application use cases on the server. Roles are per department (membership); supervisors are assigned to departments. Roles are re-read from the database on every request.                 |
| D9  | Migrations             | SQL migrations generated by drizzle-kit and checked in; applied by `scripts/db-migrate.ts` in `vercel-build` before `next build`. Migrations must be backward compatible.                              |

## Defaults in effect (not yet confirmed)

Proposed defaults from the planning report that the Phase 1 domain layer implements.
Each is isolated in one place so it can change cheaply if you decide otherwise.

| Default                                                                                     | Where                                                      |
| ------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| The Head Nurse may withdraw a submission before the Supervisor acts.                        | `schedule/state-machine.ts` (`WITHDRAW`)                   |
| Nurses do not see draft assignments before FINALIZED.                                       | `schedule/visibility.ts`                                   |
| Supervisors see a department's grid only from FINALIZED onward.                             | `authz/policies.ts` (`schedule.viewDepartment`)            |
| Change requests can be submitted from FINALIZED onward.                                     | `authz/policies.ts` (`changeRequest.submit`)               |
| Changes after approval go through a revision limited to declared dates and are re-approved. | `schedule/assignment-editing.ts`, `schedule/visibility.ts` |
| One assignment per nurse per day (ME is the only double).                                   | `rules/validate-schedule.ts`                               |
